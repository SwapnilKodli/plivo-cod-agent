Voice AI demo · built for Plivo

Riya: a Hinglish agent that confirms cash-on-delivery orders

Before a COD order ships, Riya calls the customer, reads back the order and address, offers ₹20 off to pay by UPI now, and records a decision: confirm, cancel, reschedule, or never call again. Orders refused at the door (RTO) are one of the biggest costs for Indian food and D2C brands, and this call is one of the most common voice-AI jobs on Plivo.

How it works

One WebSocket per call

Plivo dials the customer, fetches /answer, and opens a bidirectional audio stream to the server. Pipecat runs the pipeline for that call. Every speech stack sits behind the same transport, so swapping one is a config change.

What's in the repo

Four pieces

pipecat_koyal/tts.py

Koyal for Pipecat

Plivo launched Koyal on 18 Nov; Pipecat had no integration. This streams over Koyal's realtime WebSocket, maps each agent turn to a Koyal context, and cancels it server-side on barge-in. Written as an upstream PR.

app/agent.py

Hinglish agent, 7 tools

Hindi in Devanagari, English words in Latin script, the way Indian support agents talk. Tools: confirm, cancel, reschedule, fix address, UPI link by SMS, do-not-call, hang up.

app/orders.py

Guardrails in code

The 9 am to 9 pm IST calling window and the do-not-call list are checked before dialing, so the model can't talk its way past them. Every decision goes to an outcome log.

bench/

Replay benchmark

Pretends to be Plivo: streams the same scripted caller into each speech stack at real-time pace and times the reply on the wire. Free and repeatable, and it records every call.

# pipecat_koyal/tts.py: barge-in stops Koyal at the source, not just the playback
async def on_audio_context_interrupted(self, context_id: str):
    await self.stop_all_metrics()
    if context_id and self._websocket and context_id in self._opened_contexts:
        await self._websocket.send(json.dumps({"type": "cancel", "context_id": context_id}))
    await super().on_audio_context_interrupted(context_id)

What testing turned up

Found, fixed, and still open

fixed

Agent kept talking after hanging up. After end_call, the LLM was asked for another reply and said "Call end." out loud. The end-call result now skips the follow-up LLM run.

fixed

Empty address updates. On "address is fine", the model called update_address with no correction. The tool now rejects empty corrections and tells the model the address is unchanged.

fixed

Benchmark measured stale turns and could hang. When the agent hung up before the script ended, the harness reused the previous turn's timing, and once waited forever on a closed socket. It now resets timing each turn and stops when the call closes.

fixed

Gemini Live never spoke first. Realtime models wait for a user turn. The call now opens with a one-line kickoff message.

fixed

Stage directions spoken aloud. Groq's gpt-oss sometimes writes (end_call) or (Waiting for customer response) as text, and the voice read it out. A transform now removes parenthesized text and tool names before anything reaches TTS.

open

Code-mixed speech-to-text slips. Sarvam heard "galti se ho gaya, cancel kar do" as the reason "Kabulo cone." The decision was right, but the logged reason was wrong. Worth checking against real caller audio.

open

Grammatical gender. Riya once said "पढ़ लेता हूँ" (masculine). Hindi verb gender should follow the agent's persona; a prompt rule and a regression check would catch it.

next

Koyal numbers. The Koyal service is written and its message format is unit-checked, but these benchmark runs used Sarvam's voice because they ran without a Plivo account. With Plivo credentials, the Koyal stacks run unchanged.
